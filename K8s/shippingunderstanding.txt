                              2. What Kubernetes objects do we need?

For Shipping, normally:

Object	Name	Purpose
Deployment	shipping	Runs the Shipping application
Service	shipping	Makes Shipping available to other microservices

No PVC is needed for Shipping itself, because Shipping is stateless. MySQL already owns the database data.


Why does Shipping need Cart?

The Shipping service needs information associated with the current order/cart when calculating or processing shipping.

The container itself explicitly has:

CART_ENDPOINT=cart:8080

So Kubernetes DNS lets it reach:

cart:8080

without hardcoding the Cart ClusterIP.

6. Why the readiness probe is particularly useful here

This is the most important new Kubernetes concept in Shipping.

You have:

readinessProbe:
  httpGet:
    path: /health
    port: 8080

Kubernetes will repeatedly ask:

Shipping Pod
     |
     | HTTP GET /health
     |
     v
:8080

If Shipping isn't ready:

Pod = Running
Pod = NOT Ready

Therefore the Service should not send normal application traffic to that Pod until it becomes Ready.

This is different from:

Pod Running

A Java container can be Running while the application is still starting.

That's why readiness probes are very important for Java/Spring Boot-style services.
